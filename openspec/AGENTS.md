

# OpenSpec instructions

## Workflow

- Treat `openspec/specs/` as current source of truth.
- Put proposed behavior under `openspec/changes/<change-name>/`.
- Agree on proposal, specs, design, and tasks before implementation.
- Archive completed changes so source-of-truth specs match deployed behavior.

## Principles

- Specify verifiable behavior before implementation.
- Keep one focused change per change directory.
- Preserve requirements and scenarios during archive.
